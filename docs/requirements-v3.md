# 要件定義書 v3：西山公園アプリ

オープンデータ活用アプリコンテスト2026 応募作品
作成日: 2026-09-06 / 提出期限: 2026-09-30 11:00（残り24日）

v2（1日の行程を組むプランナー）を破棄する。理由は3つ。

1. テーマは「県外の人に遊びに行きたいと思ってもらう」であり、行程管理は**行くと決めた後**の道具でズレていた
2. 24日でタイムライン編集UIを作るのは分量が合わない
3. データを掘った結果、**主張として成立する発見**が出た。器より発見を運ぶことを優先する

---

## 1. 主張

このアプリが言うことは1つ。

> **ツツジで有名な西山公園の、県外から来る人にとっての狙い目は秋。**

根拠はすべて鯖江市の公開データの実測値。

| | 春（ツツジ） | 秋（紅葉） |
| --- | --- | --- |
| ピーク | 5/5 = 4,550人 | 11/16 = 1,310人 |
| 日別中央値 | 750人 | 390人 |
| 快適日（15〜25℃かつ晴/曇） | 28日 / 61日 | **30日 / 91日**（年間最多） |
| 動物園18年トレンド | +6% | **+64%** |

紅葉の見頃 × 平日 × 晴/曇 の13日間は中央値 **350人**。5/5 の **13分の1**。

夏は92日中の快適日が **3日**。公園と道の駅の来訪者比が 1.23 で、夏は公園ではなく道の駅に来ている。

### 手法の検証

日別来訪者数から機械的に導出した見頃ウィンドウが、公式の祭事期間と一致した。

| | 実測から導出 | 公式データの記載 |
| --- | --- | --- |
| ツツジ | 5/5が年間最多、2位5/4、3位5/3 | つつじまつり 5月3日〜5日 |
| 紅葉 | 11/16頂点、11/14〜11/25 | もみじまつり 11月中旬〜11月下旬 |

「見頃を当てた」ではなく「**人の動きから見頃を復元できることを公式データで検証した**」と主張できる。

### 書き方の制約

**ツツジを否定しない。** 主催は鯖江市でPRの中心はツツジ。
「地元に愛されている証拠（休日来訪者の52%が鯖江市民、5/3〜5/5に集中）+ 県外への新しい入口」
という足し算で書く。ここを外すと心証を損ねる。

## 2. 何を作るか

**1ページ。ユーザーの入力で、ページの主張そのものが書き換わる。**

Webサイトとの違いは、閲覧か双方向かにある。入力が表示を変えるだけでなく、
**結論を変える**こと。そして**その状態がURLに残り、他人に送れる**こと。

### 画面構成（単一ページ）

```
■ 主張            ← 入力で変わる。ページの結論
■ 条件入力         ← 主張のすぐ下。触ると上が即座に書き変わる
■ 季節の順位       ← 4枚が並べ替わる
■ 根拠            ← 1位の季節に合わせて中身が変わる
■ 写真            ← 1位の季節のものが出る
■ 実務情報         ← 開園時間・休園日・アクセス
■ 出典・ライセンス   ← 畳んでよいが消さない
```

フォームを主張の直下に置くのは、**触った瞬間に上が変わるのが見えないと因果が伝わらない**ため。

### 入力で変わるもの

| 入力 | 既存の型 | 変わるもの |
| --- | --- | --- |
| 目的 | `PurposeId` | 主張文、季節順位、根拠、写真 |
| 同行者 | `CompanionId` | 気温とゆとりの重み |
| 出発地・交通 | `TransportId` | 天気の重み（県外ほど天気を重視） |
| 行ける時期 | `PeriodId` | 対象日、推奨日 |
| 優先度 | `number` | 見頃 ⇄ 空いてる日 の配分。**季節順位が入れ替わる** |

### 主張文の例

| 条件 | 出力 |
| --- | --- |
| 子ども連れ・平日可・混雑回避 | 「11月18日(火)。350人の日。5/5の13分の1」 |
| ツツジ目的・休日のみ | 「5月5日は4,550人。それでも行くなら朝8時台」 |
| 夏しか行けない | 「快適日は92日中3日。屋外は朝夕、主役は動物園と道の駅」 |

**どの条件でも答えを返す。** 「夏はダメ」で終わらせない。

## 3. 実装

### 3.1 流用するもの（新規に書かない）

`src/lib` 約1,100行はそのまま使う。

- `scoring.ts` — 目的・同行者・交通で重みを変えて日を採点。**これが主張の計算エンジン**
- `seasonality.ts` — 見頃ウィンドウの導出、来訪者percentile
- `climate.ts` — 天気・気温の快適さ
- `forecast.ts` — Open-Meteo
- `holidays.ts` — 祝日（休園日判定にも使う）
- `narrative.ts` — 文の組み立て。**主張文の生成でここが主役になる**

### 3.2 新規に書くもの

**① 季節スコア（数十行）**

`scoring.ts` は日を採点している。それを季節に集約する関数を足す。

```
seasonScore(season, preferences) =
  その季節の全日を rankDays で採点し、上位N日の平均を季節の得点とする
```

上位N日の平均にするのは、「その季節に行くとしたら最良の日を選ぶ」のが実際の行動だから。
季節の平均を取ると、行かない日に引きずられて実態と合わない。

**② 主張文の生成**

`narrative.ts` を拡張。季節順位の1位と、その季節の推奨日、差を説明する数字（何分の1か）を
文に落とす。テンプレートは条件の組み合わせごとに用意せず、
「結論 + 数字 + 比較対象」の3要素を組み立てる形にする。

**③ URL永続化**

`?purpose=&companion=&transport=&period=&priority=` をクエリに持つ。
サーバー保存はしない。読み込み時に復元、変更時に `replaceState` で更新。
これで共有・再訪・OGPが同時に解決する。

**④ 1ページ化**

`data.astro`（479行）の出典・ライセンス部分を `index.astro` の下部セクションへ統合。
グラフのうち主張を支えないものは落とす。

### 3.3 やらないこと

- タイムライン、行程生成、ドラッグ操作
- 3D / WebGL
- スクロール連動アニメーション
- 複数ページ、ルーティング
- PWA、OGPの動的生成、当日モード、地図ライブラリ
- ユーザー登録、サーバー保存
- フレームワークの変更（Astro + React アイランドのまま）

## 4. データ

### 4.1 使うもの（すべて取得・検証済み）

| データ | 出所 | 役割 |
| --- | --- | --- |
| 日別来訪者数 365日 | 鯖江市 | 主張の中核。見頃・混雑・快適日 |
| 動物園 月別 18年分 | 鯖江市 | +64% トレンド |
| 公園・道の駅 月別 | 鯖江市 | 季節比較、夏の道の駅比 |
| 市区町村別割合 | 鯖江市 | 「地元の祭り」の根拠 |
| ツツジ 11種50,025株 | 鯖江市 | 実務情報 |
| 開園時間・休園日 | 総務省公共クラウド | 実務情報。CC BY 2.1 |
| 天気予報 | Open-Meteo | 推奨日の判定 |

調査の全体は `data/catalog/README.md`。

### 4.2 注意

- 日別来訪者数は Agoop の人流推計。**公園全体ではなく東側エリア**。10人単位に丸められており、0は「10人未満」
- 公共クラウドは更新日時が2017年。営業時間は現況と異なる可能性があるため取得日を明示する
- CSVは UTF-8 と Shift_JIS が混在

### 4.3 未確認（時間があれば）

- `市営駐車場情報`(XML) に西山公園の駐車場があるか
- `西山動物園の動物`(XML) に給餌時間が含まれるか
- イベントCSV 685件に西山公園開催分があるか

駐車場のリアルタイム満空フィードは実在し稼働も確認したが、
エンドポイント名・ホスト・ライセンス表記の点で**採用しない**（`data/catalog/README.md` 参照）。

## 5. デザイン

### 5.1 参照（実在するものを必ず参照する。「〜風」で済ませない）

| 参照 | 借りる要素 |
| --- | --- |
| 日経ビジュアルデータ | 日本語のタイポグラフィ×データ。行間、約物、数字の欧文扱い |
| Reuters Graphics | 主張1つを図で押し切る潔さ |
| JAL OnTrip の記事 | 写真の物量、実務情報ブロックの置き方 |

### 5.2 データの見せ方

数字を figure の横に置くのではなく、**データそのものを画面の構造にして、その上に言葉を乗せる**。

- 18年の 11月 vs 5月 → 2本の面が右へ開いていく形。その上に「+64% / +6%」
- 夏の快適日 → 92個の点のうち**3つだけ光る**。数字を書かなくても伝わる
- 一年の来訪者 → 春に鋭い山、秋になだらかな山。ピーク位置に日付

### 5.3 避けること

AI生成デザインの型に落ちない。

- クリーム色背景 + セリフ見出し + テラコッタのアクセント
- 全カード同一の角丸・同一のシャドウ
- 全角中黒で繋いだメタ情報
- 大文字英字のラベル
- 装飾としての 01/02/03 連番マーカー
- スクロール連動アニメーション

モーションは**入力に応答するもののみ**。季節順位の並べ替えと、主張文の切り替わりの2箇所。

## 6. 非機能

| 項目 | 目標 |
| --- | --- |
| 再計算 | 入力から描画更新まで 100ms 以内 |
| 対応 | iOS Safari / Android Chrome / PC Chrome・Safari 最新2版 |
| レスポンシブ | 375px〜1440px |
| アクセシビリティ | キーボード操作可、フォーカス可視、コントラスト比 4.5:1 以上、`prefers-reduced-motion` 対応 |
| 障害時 | 天気API失敗時は平年値で計算し、その旨を明示（実装済み） |
| 型 | `as` と `!` を使わない。外部境界は `unknown` で受けてパース（実装済み方針を維持） |

## 8. リスク

| リスク | 対応 |
| --- | --- |
| 「ツツジを否定した」と受け取られる | 足し算の書き方を徹底。文言レビューを提出前に1回入れる |
| 季節スコアが直感と合わない | 上位N日平均のNを調整可能にし、CLIで全条件の出力を目視確認 |
| デザインがAI生成の型に落ちる | 5.3 のリストで実装後に照合する |
| 主張が地味に見える | 数字（13分の1、92日中3日、+64%）を前面に置く。文章で盛らない |
| 手が余る | 4.3 の未確認データを潰す。それでも余れば地形の断面図 |
